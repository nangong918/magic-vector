### 推拉流基本方案

推拉流方案：


采集：Android CameraX -> YUV -> 软编、硬编 (RK) 
推流：RTMP、RTSP (TCP、UDP) 
编码：播放H.264，传输H.265
组帧与透传：SpringBoot (Netty) 
播放：ExoPlayer、FFmpeg


* 2026/1/21 方案：
  * 先剥离Android，直接使用FFmpeg，RTMP/RTSP尝试推拉流
  * 在线方案：x264 + RTMP -> 推流Nginx -> 拉流FFmpeg播放
  * 离线方案：
    * RK UDP推裸流 -> Android 组帧 -> 播放
    * RK 封装H264 UDP 推流 -> Android 直接播放


* 2026/1/22 方案：
  * UDP 裸 H264 的性能可能更高、延迟更低，但实现复杂度和稳定性更差.
  * 问题：因为RTMP（TCP）性能必UDP裸流性能差，并且SpringBoot需要获取流媒体数据交给阿里百练。
    就导致了需要两个拉流端，App2和SpringBoot端。消耗是双倍带宽。
  * 用UDP的稳定性差于TCP的RTMP，所以丢包就会出现花屏问题。方案应该设计为可选。

[Android播放RTMP](https://github.com/qingkouwei/oarplayer)

数据流：
* Camera (CameraHelper.Camera) -> YUV数据
  1. -> TextureView (SurfaceHolder) 预览
  2. -> CameraHelper (Camera.onPreviewFrame) 
     * -> VideoStream.onPreviewFrame -> LivePusherNew.onVideoFrame -> native_pushVideo (JNI) 
        * -> VideoStream::encodeVideo (YUV -> I420 -> H264 NAL)
        * 组RTMP视频包sendSpsPps;sendFrame
  3. -> 推流线程取出 `RTMPPacket` 调用推流函数 `RTMP_SendPacket`
* Camera2 (ImageReader.OnImageAvailableListener)  -> ImageReader
  1. -> TextureView (SurfaceHolder) 预览
  2. -> reader  (YUV) -> 后续与上方Camera相同
* AudioRecord (AudioStream.AudioRecord) -> PCM数据
  1. -> onAudioFrame (回调数据) -> native_pushAudio (JNI) 
     -> AudioStream::encodeData (用 FAAC 编 AAC → 组 RTMP 音频包 → 入队)
  2. 推流线程发送，启动时先发一次 AAC AudioTag（DecoderSpecificInfo）



### 媒体基本方案

Q: 我的App有记录功能。我现在是RK将h264交给Nginx的RTMP服务器然后App去调用rtmp拉流然后解码再在App上用ffmpeg播放。
现在的记录就是将实时的一段视频留存下来，保存然后上传服务器和留在本地。 那么这个功能的话怎么实现？
也就是说h264需要转为能存储的mp4？然后本地播放mp4很简单，很多适配.
主要是服务端播放存储的mp4应该会让springboot将其搞成碎尸万断的m3u8，然后app播放


A: 录制+保存视频，用FFmpeg直接将H264封装为Mp4
上传视频：小文件：单次上传；大文件：断点上传，可断点续传
获取文件：SpringBoot把MP4切片为HLS（m3u8 + ts）存储在minio，
播放的时候：Android获取 m3u8 URL 然后在ExoPlayer或者FFmpeg上进行播放。
