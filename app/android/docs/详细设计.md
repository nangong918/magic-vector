# Page

设计Page要注意MVI设计模式:
uiState: ui的状态值, 用于控制页面的ui
dataState: 数据状态, 用于存储不参与ui显示的变量例如userId, access_token
intent: 用户意图
effect: 界面的副作用
event: 事件监听, 如eventBus, 广播

## Start 页面设计

### 业务描述
- 应用启动后通过 UserManager 检查是否有已登录用户
- 有用户信息就去请求后端验证 access_token 是否有效
- 验证有效则自动跳转到 Main 页面
- 验证无效或没有用户信息则自动跳转到 Login 页面
- 启动页至少停留 1200ms，避免一闪而过

### UI大概设计
- 已实现，就是个居中显示的 Logo

### MVI大概设计
- dataState: isLoggedIn（登录状态）
- intent: Initialize（触发登录检查）
- effect: GoToMain, GoToLogin（导航用）


## Login 页面设计

### 业务描述
- 用户输入账号密码登录
- 登录成功后后端返回 userId、accessToken 等信息
- 调用 UserManager 保存用户信息到数据库
- 登录成功后跳转到 Main 页面
- 页面底部有个小链接可以跳转到注册页面


### UI大概设计
- 账号输入框
- 密码输入框（要隐藏输入内容）
- 登录按钮（账号密码没填的时候置灰不可点）
- "没有账号？去注册" 这样的文本链接

### MVI 设计
- uiState: account, password, canLogin（按钮是否可点）, isLoading（显示加载圈）, error（错误提示）
- dataState: user（登录成功后返回的用户数据）
- intent: UpdateAccount, UpdatePassword, Login, GoToRegister
- effect: NavigateToMain, NavigateToRegister, ShowError

## Register 页面设计

### 业务描述
- 用户输入账号密码注册
- 可以选头像，不选也行
- 选头像前要用 PermissionUtils 申请存储权限
- 注册成功后后端返回用户信息，调用 UserManager 保存到数据库
- 注册成功后直接跳转到 Main 页面（不用再登录一次）
- 页面底部有个链接可以跳转到登录页面


### UI大概设计
- 账号输入框
- 密码输入框
- 确认密码输入框（用来校验两次输入是否一致）
- 头像选择区域（圆形头像预览，点击可以选择图片）
- 注册按钮（信息没填完整时置灰）
- "已有账号？去登录" 文本链接


### MVI大概设计
- uiState: account, password, confirmPassword, avatarUri（选中的头像地址）, canRegister, isLoading, error
- dataState: user（注册成功后返回的用户数据）
- intent: UpdateAccount, UpdatePassword, UpdateConfirmPassword, SelectAvatar, AvatarSelected（相册返回结果）, Register, GoToLogin
- effect: NavigateToMain, NavigateToLogin, RequestStoragePermission, ShowError, ShowToast（操作成功提示）


## Main 页面设计

### 业务描述
- 底部有个导航栏，三个选项：Agent、Control、Mine
- 以前用的是 Navigation + Fragment，现在改成 Compose 的 Navigation + 组合函数
- 每个选项点开是一个页面

### Agent 页面设计

#### 业务描述
智能体相关功能都在这

##### 创建 Agent
- 如果一个 Agent 都没有，页面中间显示一个大大的创建按钮, 有Agent之后按钮不显示, 变为agent列表
- 点进去要填：头像、名称、设定（提示词）
- 填好后请求后端保存，头像文件用 MinIO 存
- 保存成功后通过 AgentManager 更新本地缓存，列表里就能看到了

##### Agent 列表
- 显示所有创建好的 Agent，数据通过 AgentManager 获取（先读缓存再刷新）
- 单击某个 Agent 就进聊天页面
- 右滑某个 Agent 进详情页面，可以查看、修改、删除
- 列表数据用 Room 做缓存，AgentManager 负责管理

##### 接收消息
- Agent 收到的消息通过 ChatService 推过来，页面上要显示
- 消息类型包括文本、表情、可能还有语音

#### UI大概设计
- 空状态：一个大大的加号按钮
- 有数据：列表展示 Agent 卡片，卡片上有头像、名称、最后一条消息预览、未读消息数红点


### Chat 页面设计

#### 业务描述
和 Agent 对话的页面

##### 视图类型
- **Call唤醒视图**：语音通话界面，有麦克风、扬声器、挂断按钮
- **文本Chat视图**：常规聊天界面，输入框+发送按钮，消息气泡展示
- **emoji表情视图**：展示Agent的表情

##### 摄像头状况
- 显示当前前置摄像头是否开启
- 可以控制摄像头的开关

##### 消息收发
- 通过 ChatService 发送消息到后端
- 接收 Agent 的回复并展示
- 消息类型：文本、表情、语音、视频

#### UI大概设计
- 顶部：Agent 头像、名称，摄像头状态图标
- 中间：消息列表（区分左右气泡，显示发送时间、已读状态）
- 底部：输入区域（可切换文本/表情模式），语音输入按钮
- Call视图：全屏或弹窗，显示通话状态



### Control 页面设计

#### 业务描述
设备控制和状态监控

##### 设备状态监控
- RK与App连接状态（蓝牙、WiFi）
- RK与SpringBoot连接状态
- RK当前选中的 Agent
- App与SpringBoot连接状态

##### 云操控平台 (Live)
- 向 SpringBoot 发送控制指令（前进、后退、转向等）
- 接收 Nginx 的 Live 推流，实时显示另一台设备的摄像头画面
- 视频录制功能，可以保存到本地

##### 离线操控
- BLE 蓝牙连接 RK 并发送指令
- 连接 RK 创建的 WiFi 热点发送指令
- Agent 指令控制台输出（调试用）

#### UI大概设计
- 顶部：连接状态卡片（4个状态指示灯）
- 中间：实时视频预览窗口（如果有推流）
- 底部：方向控制按钮（上下左右），功能按钮（录制、截图）
- 侧边或底部：控制台日志输出区域

#### MVI大概设计
- uiState: connectionStates（rkAppConn, rkServerConn, appServerConn, selectedAgent）, videoUrl, isRecording, consoleLogs, controlButtons
- dataState: deviceId, rkMacAddress, wifiSsid
- intent: RefreshConnections, SendCommand, StartVideo, StopVideo, StartRecording, StopRecording, ConnectBluetooth, ConnectWifi, ToggleConsole
- effect: ShowVideoFullScreen, SaveVideo, ShowBluetoothScan, ShowWifiList, ShowError


### Mine 页面设计

#### 业务描述
个人信息和设置

##### Setting
- 修改密码：输入旧密码、新密码、确认新密码
- 登出：退出登录，清空本地用户信息，跳回 Login 页面

##### 视频
- **云上录播记录**：显示云端存储的录制视频列表，支持播放、下载
- **本地视频播放**：显示本地保存的视频列表，支持播放、删除
- **本地视频上传云端**：选择本地视频上传到云端

#### UI大概设计
- 顶部：头像、昵称展示
- 设置选项列表：修改密码、登出（带图标）
- 视频分类 Tab：云端/本地
- 视频网格列表：封面、时长、标题、上传/下载状态

#### MVI大概设计
- uiState: userInfo, videoTabs, cloudVideos, localVideos, uploadProgress, isUploading
- dataState: userId, storageQuota
- intent: LoadUserInfo, LoadVideos, ChangePassword, Logout, PlayVideo, DownloadVideo, UploadVideo, DeleteVideo
- effect: NavigateToLogin, ShowVideoPlayer, ShowDeleteConfirm, ShowUploadSuccess, ShowError



# Service

## ChatService

- 负责和 Agent 的实时通信，比如发消息、收消息
- 需要在后台一直跑，所以要用前台服务保活
- 通信方式用 WebSocket 或者 HTTP 轮询都行，看实际需要

## VideoService

- 负责视频推流接收和录制
- 连接 Nginx 获取直播流
- 视频文件本地存储管理

# Manager

Manager 层负责业务逻辑，给上面的 Page 提供数据和功能

## UserManager

- 封装用户相关的业务逻辑
- 内存里缓存一个当前用户对象
- 提供的功能：登录、注册、登出、修改密码、获取用户信息、验证 token

## AgentManager

- 封装 Agent 相关的业务逻辑
- 内存里可以缓存 Agent 列表和当前选中的 Agent
- 提供的功能：获取列表、创建、更新、删除、按 ID 查询、与服务端同步

## ConnectionManager

- 管理各种连接状态
- 提供的功能：监控蓝牙连接、WiFi 连接、与服务端的连接状态、重连机制

## CommandManager

- 发送控制指令
- 提供的功能：发送指令到 RK（通过蓝牙/WiFi/云端）、指令队列、重试机制

## VideoManager

- 管理视频相关功能
- 提供的功能：获取云端视频列表、获取本地视频列表、上传视频、下载视频、删除视频、播放控制

# DoMain

## DO (Database Object)

**UserEntity**：
- id（自增主键）
- user_id（后端分配的用户 ID）
- account（登录账号）
- user_name（昵称）
- password（密码，加密存储）
- access_token（后端的访问令牌）
- profile_picture_url（头像地址）

**AgentEntity**：
- id（自增主键）
- agent_id（后端分配的 Agent ID）
- name（Agent 名称）
- avatar_url（头像地址）
- prompt（提示词/设定）
- user_id（所属用户）
- create_time
- update_time

**MessageEntity**：
- id（自增主键）
- message_id
- agent_id
- conversation_id
- content
- type（text/emoji/voice）
- timestamp
- is_sent（true 自己发的，false 收到的）
- status（sending/sent/delivered/read）

**VideoEntity**：
- id（自增主键）
- video_id
- title
- cover_url
- duration
- size
- local_path（本地路径）
- cloud_url（云端地址）
- upload_status
- create_time

## DTO (Data Transfer Object)


### Request
- LoginRequest：account, password
- RegisterRequest：account, password, userName, profilePicture
- CreateAgentRequest：name, prompt, avatar
- UpdateAgentRequest：agentId, name, prompt, avatar
- SendMessageRequest：agentId, content, type
- ControlCommandRequest：deviceId, command, params
- UploadVideoRequest：videoId, file

### Response
- LoginResponse：userId, userName, accessToken, profilePictureUrl
- RegisterResponse：同 LoginResponse
- AgentResponse：agentId, name, avatarUrl, prompt, createTime
- AgentListResponse：List<AgentResponse>
- MessageResponse：messageId, content, type, timestamp
- VideoListResponse：List<VideoResponse>
- ConnectionStatusResponse：各连接状态
